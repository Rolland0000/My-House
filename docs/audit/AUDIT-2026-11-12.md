### 2.1 Moyenne

#### A1-02 — Budget de devinettes OTP renouvelable sans limite

| | |
|---|---|
| Sévérité | **Moyenne**. Le vecteur noté AV:N/AC:H/PR:N/UI:N/C:H/I:H/A:N donne 7.4 (Haute). Auditeur et vérificateur retiennent Moyenne parce que l'attaque est probabiliste et très bruyante (environ 1 440 e-mails par jour vers la victime). **À arbitrer.** L'impact est Haut si la cible est l'adresse `ADMIN_BOOTSTRAP_EMAIL`. |
| CWE / ASVS | CWE-307 / ASVS V2.2.1, V2.7.x |
| Fichier:ligne | `backend/src/modules/auth/service.rs:175-182` (réinsertion de `attempts: 0` à chaque `otp_request`), `:247-262` (plafond par code seulement), `:165` (seul frein : cooldown de 60 s par e-mail) |
| Preuve | Code : `challenge_cache.insert(otp_key(email), AuthChallenge::PendingOtp(PendingOtp { code_hash, is_new, attempts: 0 }))`. Live (deux fois, par l'auditeur puis par le vérificateur) : cycle 1 avec 3 mauvais codes (`401 401 401`), puis le bon code renvoie `OTP_INVALID` ; 62 s plus tard, nouveau code, 2 mauvais, puis le bon code renvoie `{"data":{"is_new_user":true…`. Soit 5 essais faux en 63 s sur le même e-mail, suivis d'un succès. |
| Statut | Confirmé (reproduit) |
| Impact | 3 chances sur 10⁶ par minute, sous la limite IP (100/min). Calcul de l'auditeur : environ 12 % de réussite en 30 jours sur un compte ciblé ; en non ciblé, environ un succès tous les 9 jours par IP (création d'un compte au nom d'une adresse tierce). |
| Correction | Compteur d'échecs par e-mail (et par IP) indépendant du code et conservé plusieurs heures, avec **backoff croissant** du cooldown après N échecs. Ne pas remettre `attempts` à 0 tant que la fenêtre n'a pas expiré. ⚠ Voir §2.6 : un verrouillage dur est à éviter, il permettrait de bloquer la connexion d'une victime. |

**Écarts entre le code et la spec (contrat d'API) :**

- **SQL :** aucune injection ; chaque `format_args!` et `push` n'interpole que des constantes.
- **Rotation du refresh :** atomique (6 rondes de 12 refresh simultanés, un seul jeton par ronde).
- **Réutilisation hors fenêtre :** la réutilisation d'un refresh révoque toute la famille.
- **JWT :** algorithme épinglé ; `none`, HS512 et mauvaise clé renvoient 401.
- **Cookie :** conforme à la décision verrouillée.
- **Suspension :** effet immédiat.
- **BOLA/IDOR :** environ 120 requêtes, toujours 404 avec un corps identique.
- **RBAC :** 403 et 401 corrects.
- **Mass assignment :** champs interdits ignorés.
- **CORS :** liste blanche exacte.
- **PII publique :** aucun téléphone ni e-mail dans les réponses publiques.
- **5xx :** message générique.
- **Clés de stockage :** générées à 100 % par le serveur.

- **Async :** aucune I/O bloquante en chemin de requête, aucun verrou tenu à travers `.await`.
