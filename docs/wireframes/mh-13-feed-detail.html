Comportement

GET /listings
  • Query params : city, type, owner_id, page, per_page (FEED-05).
  • Chaque carte affiche cover_photo_url, title, city + neighborhood, price, type (FEED-02).
  • Clic sur une carte → navigation vers /listings/:id (FEED-03).
  • Filtres ville/type déclenchent un nouvel appel avec les query params correspondants. owner_id n'est pas exposé en filtre visible ici — réservé à un usage interne (ex. page profil propriétaire).
  • Pagination illustrée avec per_page = 30 — voir flag ci-dessous sur l'incohérence de spec.

Comportement

  • Squelette affiché pendant l'appel réseau initial, un changement de filtre, ou un changement de page.
  • La barre de filtres reste interactive pendant le chargement (pas de verrouillage) — à confirmer avec le produit si ce n'est pas le comportement souhaité.

Comportement

  • pagination.total = 0 dans la réponse → état vide, pas de composant pagination affiché.
  • Deux variantes de copy à prévoir côté FE : « Aucun résultat pour ces filtres » (filtres actifs, illustré ici) vs « Aucun bien disponible pour le moment » (feed complet vide, aucun filtre).
  • « Réinitialiser les filtres » relance GET /listings sans query params.

Comportement

GET /listings/:id
  • Endpoint public, aucune auth requise. Champs : media[] (galerie), description, price, surface_m2, rooms, city/neighborhood, owner{first_name,last_name,avatar_url} — jamais phone (DET-02).
  • Galerie scrollable horizontalement, tri par media[].position (DET-01).
  • Bouton « Contacter » visible même non authentifié. Le clic déclenche GET /listings/:id/contact, qui nécessite un JWT (seeker ou owner) — si non connecté, hypothèse de redirection vers le flow d'auth (MH-12, écran Email) avant reveal. Ce comportement n'est pas documenté dans le contrat API, à valider en dev.

Comportement

  • Squelette pendant l'appel GET /listings/:id. Bouton de contact désactivé tant que les données ne sont pas chargées.

Comportement

GET /listings/:id/contact
  • 200 → { phone } affiché à la place du bouton, remplace la zone de contact.
  • 404 LISTING_NOT_FOUND → le bien a pu être supprimé/désactivé entre le chargement de la page et le clic (race condition) ; prévoir un fallback vers l'état « not-found ».
  • Le message d'avertissement (DET-01) reste visible même après reveal — il concerne la transaction, pas seulement l'obtention du numéro.

Comportement

  • 404 sur GET /listings/:id — bien supprimé ou statut non disponible (même code d'erreur que sur /contact, cf. table de tests TECHNICAL_SPEC_MVP.md).
  • CTA de retour vers le feed plutôt qu'un rechargement de la même URL.

Décisions & hypothèses prises pendant cette session

⚠ Incohérence de pagination entre spec fonctionnelle et technique Le cahier des charges (FEED-04, Must) impose 30 résultats/page par défaut. TECHNICAL_SPEC_MVP.md §4.3 documente un défaut de 20 (max 50) pour GET /listings. Wireframe illustré avec 30 conformément au Must fonctionnel — à trancher avant implémentation FE/BE, pas une décision silencieuse de ce wireframe.
Texte du message d'avertissement contact (DET-01) illustratif Le cahier des charges demande seulement « un petit message d'avertissement concernant tout échange et transaction » sans texte précis. Le wording affiché ici est une proposition, à valider par le produit/légal avant dev — même logique que les valeurs de rate-limit illustratives dans MH-12.
Redirection vers l'auth flow si « Contacter » sans être connecté /listings/:id/contact exige un JWT ; le comportement pour un visiteur non authentifié n'est pas documenté dans le contrat API. Hypothèse prise en session : redirection vers l'écran Email du flow OTP (MH-12), à confirmer.
Barre de filtres ville + type ajoutée (FEED-05) Ajoutée sur demande explicite de cette session. Le filtre owner_id reste volontairement absent de l'UI générique du feed — c'est un paramètre technique utilisé quand on arrive depuis la page d'un propriétaire, pas un filtre que le seeker manipule directement.
Devise affichée en FCFA dans les exemples Illustratif pour le marché Afrique francophone (cohérent avec MH-12 : indicatif +225/+221). Le format d'affichage prix pour le marché France (€) n'est pas encore défini — lié au blocker monétisation déjà noté dans CLAUDE.md.
