1Step 1 — “Plan & Brass” foundations + public feed · English, FCFA, approved card 1f + rule 1j

What I read, what I assumed, what is still blocked

Wireframes: found

docs/wireframes/ holds all four flows (auth, feed + detail, listing management, owner request) plus DESIGN_TOKENS.md. I keep their functional structure and work only the visual layer.

Repo tokens are replaced

index.css currently runs cream #f5f4f0 + terracotta #a8380f — the exact pair the brief rules out. Plan & Brass substitutes token for token inside the @theme block. No Tailwind class name changes, so no shared component gets rewritten.

Ink on brass, never white

White on brass-500 lands at 2.4:1 — under AA. So the primary CTA is brass with an ink-900 label (5.3:1). Happy side effect: it reads as an engraved brass plate rather than a SaaS button.

Currency: FCFA, one open detail

Prices now render as 400 000 FCFA / month. formatPrice returns no symbol today, so the unit is appended in the view layer. Open question for step 2: French listings priced in FCFA read oddly — do you want a per-listing currency field, or is FCFA the single MVP currency including France?

English now, FR/EN later

All UI copy is English, matching labels.ts. Two things to keep in mind for the future translation: formatPrice hard-codes Intl.NumberFormat("fr-FR"), and Archivo was picked partly for French diacritics — it holds both languages, so no type change is needed when FR ships.

Photography: still to replace

The 12 supplied images are high-end stock (pool villas, decorator bedrooms). I kept the six that pass for ordinary rooms and left labelled slots where modest and West-African context is needed. A real photo set is still missing.

Brass budget on the approved card

1f spends brass on every price plate, so a full brass “Verified” badge on the same card would dilute the seal. On the card the seal shrinks to a white label with one brass dot; the full brass badge stays for the listing detail page, where it appears once.

Missing components (proposed, not improvised)

RootLayout is a bare Outlet. To add under shared/components: SiteHeader (role: "public" | "seeker" | "owner" | "admin"), SiteFooter, Badge (tone, size), DimensionRule, EmptyState, Skeleton. Props spelled out in step 2. Note that About and Contact are new routes — router.tsx has no entry for them yet.

One shadow in the whole product — 0 10px 26px -8px rgba(22,35,61,.26), tinted with ink rather than neutral grey — reserved for modal, dropdown and toast. A listing card has none: depth comes from pure white sitting on paper.

Motion

120 ms ease-out — border and fill on hover. Nothing else moves: no lift, no scale.

200 ms ease-out — floating elements entering.

One orchestrated moment — OTP code validation. Under prefers-reduced-motion everything drops to 0 ms.
